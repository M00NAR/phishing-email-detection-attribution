## 1. What the project does

Given an email, we answer two questions:

1. **Detection:** is it *Legitimate* or *Phishing*?
2. **Attribution:** if phishing, was it written by a *human* or *generated by AI*?

So every email ends up in one of three classes: **Legitimate**, **Human-Phishing**, **AI-Phishing**.

We focus on **interpretable linguistic features** and a **Naive Bayes** classifier. We don't
use a black-box neural model. The research claim is that a small, statistically justified
feature set can detect phishing and separate human-written from AI-written phishing.

## 2. Data

| Source | Used as |
|---|---|
| Enron emails | Legitimate |
| Nazario phishing corpus | Human-Phishing |
| LLM-generated phishing | AI-Phishing |
| CLAIR advance-fee-fraud corpus | Extra human phishing (generalization experiments) |

- `training_set.csv` has **4,491 emails**: 1,497 in each class (balanced).
- `holdout_set.csv` has **8,465 emails**: 4,934 Legitimate, 3,489 AI-Phishing and
  42 Human-Phishing.

The cleaned CSVs are in `01_data_cleaning/`. The raw source corpora are **not** in the repo.

## 3. Method in one page

```
raw emails ──► 01 clean & split ──► 02 extract 26 features ──► 03 statistical gate
                                                                     │
                       ┌─────────────────────────────────────────────┘
                       ▼
     04/05 Two-stage Naive Bayes
        Step 1: Legitimate vs Phishing
        Step 2: Human-Phishing vs AI-Phishing (only if Step 1 says Phishing)
```

**Features:** there are 26 in total, in two kinds.
- **Continuous (16):** perplexity and log-probability from a trigram language model, lexical
  diversity, parse depth, clause density, sentiment variance, spelling-error density,
  punctuation entropy, urgency and imperative density, pronoun use, and length.
- **Categorical flags (10):** generic greeting, threat clause, sensitive-info request,
  multiple URLs, ALL-CAPS words, bracketed call-to-action, RE:/FW: subject, sign-off,
  quoted reply, attachment mention.

**Feature selection (statistical gate, `03_`):** a feature is kept only if it is both
statistically significant and has a meaningful effect size.
- Significance comes from Kruskal-Wallis or Mann-Whitney tests for continuous features,
  and chi-square tests for flags.
- Effect size is measured with Cohen's d or Cramer's V.
- p-values are corrected with Benjamini-Hochberg FDR.
- The kept features are saved in `locked_features_*.json`.

**Classifier (`04_`, `05_`):**
- **Rank-Binned Naive Bayes** handles the continuous features, and **Categorical Naive
  Bayes** handles the flags.
- A **meta Naive Bayes** combines the two posteriors.
- A **length gate** skips the variance-based features for emails under 30 words, because
  they are unreliable on short text.

## 4. Current results

From `05_final_model_and_evaluation/evaluation_summary_*.json`:

| Experiment | Step 1 acc. | Step 2 acc. | End-to-end acc. |
|---|---|---|---|
| **Final model**, original holdout | 0.867 (recall 0.984, FPR 0.217) | 0.983 | **0.861** |
| Final model, holdout + CLAIR rows (`augmented`) | 0.655 | 0.976 | 0.650 |
| Model trained on CLAIR only (`clair`) | 0.940 (FPR 0.054) | 0.988 | 0.938 |

How to read this:
- Step 1 recall is high, but the false-positive rate is about 22%: many legitimate emails
  are flagged as phishing.
- Accuracy drops on CLAIR advance-fee fraud. This style of fraud was not in training, so
  generalization is weak.
- Step 2 holdout has only 42 Human-Phishing emails, so the Step 2 numbers are dominated by
  the AI-Phishing class.

## 7. How to contribute

1. Create a branch: `git checkout -b <your-name>/<short-topic>`.
2. Keep the folder structure flat. Put a new script in the matching numbered folder, next
   to the data it reads or writes.
3. Don't overwrite locked results (`locked_*.json`, `evaluation_summary_*.json`). Write new
   experiments to new files with a clear suffix, for example `_v3` or `_myexperiment`.
4. Keep every file under 100 MB (GitHub's limit).
5. Open a pull request that explains what changed and why.

## 8. Glossary

| Term | Meaning |
|---|---|
| `v2` | The accepted 26-feature set with the length gate |
| `final` | The accepted production model |
| `clair` | Separate experiment: model trained only on the CLAIR corpus |
| `augmented` | Original holdout plus CLAIR rows |
| Length gate | Skip variance features for emails under 30 words |
| Statistical gate | Significance + effect-size + FDR filter used to choose features |
